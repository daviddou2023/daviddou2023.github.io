# 一、HTTP 请求与响应

HTTP Request 由 method、path、head 和可选请求体组成。请求体常用JSON; Content-Type 表示发送的数据格式，Accept表示客户端希望接收的格式。

HTTP Response 由状态码（status）、响应头和可选响应体组成。

HTTP是无状态协议：每次请求都需要携带处理该请求所需的信息，服务器不会自动记住上一次请求。



# 二、HTTP 方法和幂等性

理解每个方法表达的操作意图：

- GET：读取资源；应该是安全的，不应产生业务副作用

- POST：创建资源或者触发操作；通常不保证幂等

- PUT：整体替换资源；语义上是幂等的

- PATCH：部分修改资源；语义上是幂等的。

- DELETE：删除资源

幂等：对同一目标执行一次和重复执行多次，最终业务状态是一样的。它对超时重试和网络中断后的重试很重要。但是幂等不代表每次响应都一样。



# 三、状态码与接口定义

- 200：请求成功并且有响应内容

- 201：成功创建资源，适合任务创建成功

- 400：请求本身不符合接口要求

- 401：没有有效身份凭证

- 404：资源不存在或者接口选择不暴露该资源

- 429：请求过于频繁，触发限流

- 502：网关或者代理从上游服务收到无效响应

- 503：服务暂时不可用，例如过载或者维护

FastAPI请求校验失败通常返回422 unprocessable entity，说明请求的HTTP格式和语法是完全正确的，但是内部的数据内容不符合pydantic模型的校验规则；返回400 bad request，说明请求的HTTP本身格式或者协议就是错的。



# 四、FastAPI 基础

FastAPI有一些基础概念：

- 路由：把HTTP方法和URL映射到处理函数

- 路径参数是URL的一部分（/books/1），查询参数是附加条件（？author=xxx）。路径参数用于找某一个，查询参数用于筛选一批。

- pydantic模型：定义输入和输出结构；字段类型、必填项和约束会在运行时校验

- 依赖注入 Depends：复用公共逻辑，例如获取数据库会话或者当前用户；除此之外，还可以在测试中临时替换任何一个依赖，不用修改业务代码。

- 错误处理：用HTTP异常表达客户端可理解的错误，不把内部错误细节直接暴露给客户端。

- Async def 和 def：异步适合配合异步I/O；函数写成async 不会让阻塞操作变快

运行方面，Uvicorn是ASGI服务器，负责接收HTTP请求并运行FastAPI应用；/docs则是FastAPI根据接口定义生成的交互式文档。

![Image](assets/images/61cf92b4e4/image-02.png)

用户在浏览器界面的每一次点击，都是浏览器向FastAPI后端发送一次HTTP请求，FastAPI后端上是部署有你写的FastAPI应用代码的服务器，后端收到请求后，执行业务（查数据库、做计算、调用其他服务等），把执行完后的结果打包成JSON，并附上状态码，发回给浏览器，浏览器拿到JSON内容后，通过前端渲染出界面让用户看到结果。

- FastAPI ：用于构建 Web API 的高性能python框建，基于starlette（负责web/HTTP的处理部分）技术和Pydantic（负责基于python类型的数据校验和转换功能）技术。

- FastAPI 后端 ：使用 FastAPI 框架构建的服务器端程序和服务

### 4.1.4 POST 方法提交数据

POST 方法用于提交数据，比如用户创建了一个新的书籍，前端把新的书名和作者打包成JSON发给后端

```Python
from pydantic import BaseModel
@app.post("/books")
async def create_book(book: BaseModel):
    new_id = max(b["id"] for b in books) + 1
    new_book = {"id": new_id, "title": book.title, "author": book.author}
    books.append(new_book)
    return new_book
```

当用户发送 `POST /books` 并附带 JSON 请求体时，FastAPI 内部做了这几步：

1. 读取 HTTP 请求体中的原始 JSON 字符串

2. 尝试解析成 Python 字典

3. 用 `BookCreate` 模型校验：字段是否齐全？类型对不对？

4. 如果校验失败，立即返回 422 Unprocessable Entity，不会执行async函数

5. 如果校验通过，构造一个 `BookCreate` 实例传入你的函数

### 4.1.5 PUT 和 DELETE

`PUT` 通常表示用请求提供的数据更新或替换资源，重复提交同一份数据后，资源最终状态应该相同，因此它具有幂等语义。如果只想修改某一个字段，通常会设计 `PATCH` 接口

```Python
@app.put("/books/{book_id}")
async def update_book(book_id: int, book: BookCreate):
    for b in books:
        if b["id"] == book_id:
            b["title"] == book.title
            b["author"] == book.author
            return b
    return {"error": book not found}
```

### 4.1.6 响应模型和状态码

```Python
class BookOut(BaseModel):
    id: int
    title: str
    author: str

@app.post("/books", response_model=BookOut, status_code=201)
```

`response_model=BookOut`：明确规定响应应包含 `id`、`title`、`author` 这些字段。FastAPI 会校验并按模型整理响应数据，也会在 `/docs` 里展示响应结构。

`status_code=201`：明确告诉客户端“图书已创建”。不指定时，成功响应默认是 `200 OK`；`201 Created` 更准确地表达创建资源成功。

![Image](assets/images/61cf92b4e4/image-14.png)

常用的状态码：

- `200 OK`：一切正常（默认）

- `201 Created`：创建成功

- `204 No Content`：删除成功，无需返回内容

- `400 Bad Request`：请求格式错误

- `404 Not Found`：资源不存在

- `422 Unprocessable Entity`：数据校验失败（FastAPI 自动返回）

## 4.2 数据校验

### 4.2.1 pydantic校验

pydantic是python的数据校验库，FastAPI高度集成。

```Python
from pydantic import BaseModel

class UserCreate(BaseModel):
    username: str
    email: str
    password: str
    age: int | None = None
    
```

当用户发送POST时候，FastAPI会接收完整的JSON字符串{"username": alice, "email": abc@gmail.com}，校验发现"password"字段缺失，不符合pydantic数据格式，直接返回422错误，只有严格满足UserCreate的数据格式，才算校验通过。这也就意味着pydantic保证了传入的函数是一个干净的UserCreate对象。

### 4.2.2 给字段加规则：Field()

字段类型检查只是第一步，除此之外字段取值还会有要求，`Field()`用来给 pydantic添加校验规则和说明。

```Python
from pydantic import BaseModel, Field
class UserCreate(BaseModel):
    username: str = Field(min_length=3, max_length=20, description="用户名") # description 在docs中展示
    email: str = Field(pattern=r"^[\w.-]+@[\w.-]+.\w+$")
    password: str = Field(min_length=8)
    age: str | None = Field(default=None, ge=0, le=200)
```

### 4.2.3 响应模型防止数据泄露

以上 UserCreate 字段中有password字段，如果直接返回 UserCreate完整字段给前端，就把密码暴露了，因此不能返回 UserCreate。

```Python
class UserCreate(BaseModel):
    username: str
    email: str
    password: str
    age: int | None = None

class UserOut(BaseModel):
    username: str
    email: str
    age: str | None = None
    
@app.post("/users", response_model=UserOut)
async def create_user(data: UserCreate):
    ...
    return new_user
```

`response_model=UserOut`可以过滤掉不存在于UserOut模型中的字段。可以保护隐私数据。

### 4.2.4 嵌套模型：处理复杂数据结构

例如在电商购物场景中，用户创建一个订单，订单要符合 `OrderCreate `格式，这个订单里包含多种商品，每种商品都要符合 `OrderItem` 格式。

```Python
class OrderCreate(BaseModel):
    product_name: str
    quantity: int = Field(ge=0)
    price: float = Field(ge=0)
    
class OrderItem(BaseModel):
    customer_name: str
    items: list[OrderCreate] # 嵌套了 OrderCreate模型
    address: str
@app.post("/orders")
async def create_order(order: OrderItem):
    total = sum(item.quantity * item.price for item in order.items)
    return {"Total": total, "amount": len(order.items)}
    
```

对应的JSON 请求体格式：外层是OrderItem，内层是 OrderCreate，必须层层校验都过关。

```JSON
{
  "customer_name": "张三",
  "address": "北京市海淀区",
  "items": [
    { "product_name": "iPhone", "quantity": 1, "unit_price": 5999.0 },
    { "product_name": "AirPods", "quantity": 2, "unit_price": 999.0 }
  ]
}
```

### 4.2.5 枚举类型：限制可选值

如果某个字段只能取固定的几个值（如订单状态：待付款、已付款、已发货），用 `Enum` 比用字符串更安全：

```Python
from enum import Enum
class OrderStatus(str, Enum):
    PEEDING = "pedding"
    SHIPPED = "shipped"
    COMPLETED = "completed"
    PAID = "paid"
class OrderUpdate(BaseModel):
    status: OrderStatus
```

## 4.3 依赖注入

> 如果图书API有十个接口需要“登录当前用户信息”，必须要在十个接口里重复写“从请求头里查找令牌 -> 解析令牌 -> 查验用户身份是否存在”的流程。更麻烦的是如果上述流程变了，必须在十个接口中同步改一遍。
> 
> 

FastAPI的 Depends 把公共逻辑写成一个函数，然后在需要的地方注入。

### 4.3.1 Depends：把公共逻辑抽出来

```Python
from fastapi import FastAPI, Header, HTTPException, Depends
from typing import Annotated
from pydantic import BaseModel

class User(BaseModel):
    name: str
    password: str

class BookCreate(BaseModel):
    title: str
    author: str

def verify_token():
    pass

# Annotated 表示前面变量的来源是后面部分
async def get_current_user(authorization: Annotated[str, Header()]) -> User:
    # Header 的格式：Authorization: Bearer abc123
    token = authorization.replace("Bearer ", "")
    user = verify_token(token)
    if not user:
        raise HTTPException(401, "Invalid token")

app = FastAPI()

@app.get("/books")
async def list_book(user: Annotated[User, Depends(get_current_user)]):
```

### 4.3.3 yield：管理资源的创建与释放

数据库连接、文件句柄这类资源用完要释放掉，`yield` 让依赖函数变成上下文管理器：

```Python
async def get_db():
    db = create_database_connection()
    try:
        yield db
    finally:
        db.close()
```

FastAPI 将它用作依赖时，执行顺序大致是：

1. 调用 `get_db()`，执行到 `yield db`暂停。

2. 把 `db` 提供给路由函数。

3. 路由函数处理请求。

4. 请求处理结束后，FastAPI 恢复执行 `get_db()`，随后运行 `finally` 中的清理代码。

`yield` 前准备并提供资源，`yield` 后的 `finally` 负责请求结束时清理资源。



### 4.3.4 依赖覆盖

这是依赖注入最强大的特性。测试中你可以临时替换任何一个依赖，不用修改业务代码。


# 六、RESTful

RESTful是接口的设计规范，而FastAPI是实现这一规范的python后端开发工具。

- **RESTful 是一种架构风格**。它规定了网络接口应该如何设计，例如用名词定义资源路径（如 `/users`），并用标准的 HTTP 方法（`GET`、`POST`、`PUT`、`DELETE`）来表示对资源的操作。

- **FastAPI 是一个 Python Web 框架**。它是一个具体的编程工具包，用来编写后端代码、接收网络请求并返回数据。
